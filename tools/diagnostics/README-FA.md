# جمع‌آوری شواهد تأخیر Windows / VMware و VM

این ابزارها تشخیصی‌اند؛ هیچ اجازهٔ ساخت یا انتشار ایجاد نمی‌کنند. شاخص ناموجود، گزارش ناقص و وقفهٔ پایش معادل صفر خطا نیستند. برای مبنای واقعی این نصب، [گزارش مرحلهٔ هفتم](../../docs/ATLAS-STAGE-7-FA.md) را بخوانید.

## اجرا روی میزبان Windows واقعی VM

میزبان، همان کامپیوتری است که VMware و فایل دیسک این VM روی آن قرار دارند؛ این ویندوز با کامپیوتر اجرای Codex متفاوت است. فایل `collect-windows-host.ps1` را روی آن میزبان قرار دهید. PowerShell را با کاربری که VM را اجرا می‌کند باز کنید و مسیر واقعی پوشهٔ دارای فایل `.vmx` را بدهید. مسیر خروجی باید تازه و بیرون از پوشهٔ VM باشد. مسیرهای زیر فقط مثال‌اند:

```powershell
powershell -NoProfile -File .\collect-windows-host.ps1 `
  -VmDirectory "D:\VMs\atlas" `
  -OutputDirectory "D:\AtlasDiagnostics\atlas-run-01" `
  -Seconds 120
```

VM را روشن و سازنده را paused نگه دارید؛ بار import یا آزمون storage ایجاد نکنید. ابزار تنظیمات، فایل دیسک، snapshotها و سرویس‌ها را تغییر نمی‌دهد. فقط پوشهٔ خروجی را می‌سازد. اسکریپت سیاست اجرای PowerShell را تغییر نمی‌دهد.

خروجی شامل نسخهٔ سیستم و VMware در صورت دسترسی، RAM میزبان، شاخص‌های paging و دیسک، مصرف فرایند VMware، فهرست اندازهٔ فایل‌های دیسک/snapshot، تنظیمات سخت‌افزاری منتخب VMX، رویدادهای storage و خطوط مرتبط از لاگ VMware است. VMX خام و کلیدهای رمزنگاری صادر نمی‌شوند. فایل VMDK/VMEM خوانده یا کپی نمی‌شود؛ فقط metadata فایل‌ها ثبت می‌شود. فایل‌های checksum نیز تولید می‌شوند.

بازهٔ تاریخی پیش‌فرض خطای شناخته‌شده، **۲۰۲۶-۱۰-۲۹ از ۰۵:۵۲ تا ۰۵:۵۸ UTC** است. نمونه‌برداری زنده از زمان اجرای ابزار آغاز می‌شود؛ اندازه‌گیری امروز، فشار حافظه یا دیسک گذشته را اثبات نمی‌کند. خطوط لاگ منتخب از tail چهار فایل اخیرند و پوشش آن بازه تضمین نشده است. برای بازه‌ای دیگر، `-FailureStart` و `-FailureEnd` را با timestamp دارای `Z` بدهید.

`collection-errors.json` و Status هر counter بخشی از نتیجه‌اند. دسترسی محدود، counterهای با نام محلی یا نبود رویداد ممکن است داده را unavailable کند؛ آن‌ها را با صفر جایگزین نکنید. در این حالت ابتدا همان دسترسی یا نام counter بررسی می‌شود. خروجی فعلی برای تشخیص است و اجازهٔ افزایش RAM VM، تغییر scheduler، غیرفعال‌کردن آنتی‌ویروس یا تغییر تنظیمات VMware نیست.

پوشهٔ خروجی را ZIP کنید و برای بررسی بعدی در همین گفتگو ارائه دهید. مسیر VM، نام دیسک‌ها و بخش‌های مرتبط لاگ داخل گزارش هستند؛ credential یا دسترسی تازه‌ای برای اجرای خود ابزار لازم نیست.

## پایش بیرون از VM

`passive-guest.py` روی Linux مهمان فقط `/proc`، cgroupها و هویت چهار کانتینر شناخته‌شده را می‌خواند. خروجی JSONL با flush هر نمونه، زمان monotonic، شمارنده‌های CPU/حافظه/I/O و خطای صریح برای metric ناموجود دارد. بعد از وقفه، نمونهٔ جبرانی ساختگی تولید نمی‌شود. timestampهای نانوثانیه‌ای به‌صورت رشته صادر می‌شوند تا از دست رفتن دقت JSON در JavaScript رخ ندهد.

`observe-external.mjs` باید روی کامپیوتری خارج از VM اجرا شود. یک تونل موقت OpenSSH فقط روی loopback باز می‌کند و هویت guest collector و Martin را کنترل می‌کند. تمام پاسخ‌های کاشی با hash baseline قبلی و deadline پنج‌ثانیه‌ای بررسی می‌شوند. ساعت و event loop این شاهد مستقل از VM است؛ خودِ شبکه، تونل و SSH مهمان همچنان در مسیر اندازه‌گیری‌اند. این ابزار، HTTP عمومی gateway یا ظرفیت زیر بار را اندازه نمی‌گیرد و worker را کنترل نمی‌کند.

پیکربندی خصوصی نمونه:

```json
{
  "host": "172.16.20.36",
  "user": "owner",
  "collector": "/absolute/path/passive-guest.py",
  "targetIp": "<inspected-private-Martin-IP>",
  "martinId": "<actual-Docker-container-ID>",
  "collectorSha256": "<SHA256-of-exact-installed-collector>",
  "seconds": 120,
  "identityFile": "<private-SSH-key-path>",
  "knownHostsFile": "<verified-known-hosts-path>",
  "baselineFile": "<previous-verified-report-with-tile-hashes>"
}
```

```sh
node tools/diagnostics/observe-external.mjs PRIVATE_CONFIG NEW_REPORT
```

کلید خصوصی و پیکربندی را وارد evidence یا Git نکنید. ابزار رمز عبور ذخیره نمی‌کند. خروجی و فایل partial باید تازه باشند؛ گزارش قبلی جایگزین نمی‌شود. پایان ناقص SSH، فقدان آخرین رکورد مهمان، عدم تطابق هویت یا شکست HTTP خروج ناموفق ایجاد می‌کند. وقفهٔ بیش از ۲٫۵ ثانیه در جریان نمونه‌ها یا event loop، پیوستگی را نامعتبر می‌کند؛ این آستانه فقط کیفیت جمع‌آوری تله‌متری است و deadline پنج‌ثانیه‌ای کاشی را تغییر نمی‌دهد. تونل پس از پایان بسته می‌شود.

## تفسیر و گام بعدی

PSI زمان انتظار منابع را اندازه می‌گیرد، نه علت یکتای خرابی؛ محدودیت cgroup می‌تواند خودِ انتظار I/O ایجاد کند. شمارنده‌های sda و dm لایه‌های یک مسیرند و جمع نمی‌شوند. مبنا: [مستند PSI کرنل](https://docs.kernel.org/accounting/psi.html) و [کنترل I/O در cgroup v2](https://docs.kernel.org/admin-guide/cgroup-v2.html).

اشتراک storage میزبان/مهمان و کمبود حافظهٔ میزبان از مسیرهای شناخته‌شدهٔ افت عملکرد VMware هستند، اما در این نصب هنوز اثبات نشده‌اند. بررسی میزبان با [راهنمای VMware برای I/O](https://knowledge.broadcom.com/external/article?legacyId=1008885) و [راهنمای تشخیص Workstation](https://knowledge.broadcom.com/external/article?articleNumber=305364) هم‌راستاست. تنظیمات پیشنهادی در آن صفحات را بدون اندازه‌گیری و تطبیق با نسخهٔ واقعی VMware اعمال نکنید.

ابتدا شواهد میزبان با زمان خطا تطبیق داده می‌شود؛ سپس تغییر محدود و قابل بازگشت انتخاب و آزمون می‌شود. موفقیت baseline کم‌بار مجوز تکرار import ایران نیست.
