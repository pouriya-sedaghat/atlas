# وضعیت مرحلهٔ اول Atlas

تاریخ: ۲۰۲۶-۱۰-۲۷ — وضعیت: مرحلهٔ ارزیابی زیرساخت و موتور کاشی تکمیل شده؛ مهاجرت سرتاسری هنوز انجام نشده است.

## محدودهٔ پیاده‌سازی

- آرشیو کامل primitives در `osm_raw`، مستقل از جدول‌های موقت osm2pgsql؛ مسیر tagged و untagged، ترتیب ارجاعات، tags و metadata موجود حفظ می‌شوند.
- ممیزی دوگذری ورودی با libosmium، SHA-256، شمارش، کنترل ترتیب/تکرار/ارجاع و digest معنایی برای مقایسهٔ تمام رکوردها پس از import.
- آزمایشگاه Docker جدا، نقش‌های مستقل import/tile، فایل‌های اعتبارنامهٔ خصوصی، imageهای ثابت و SQL یکسان برای Martin و pg_tileserv.
- کتابخانهٔ تراکنشی ثبت release و نشست: انتشار با کنترل generation، حفظ نسخهٔ نشست قدیمی، lease درخواست، بازنشستگی، مهلت و مجوز حذف غیرقابل استفادهٔ مجدد.
- سیاست پایه: ۳۰ دقیقه بی‌فعالیتی، سقف مطلق ۲۴ ساعت؛ نگهداری حداقل سه انتشار موفق و حفاظت current/previous، نشست معتبر، درخواست در حال اجرا، وابستگی build و pin دستی.

ثبت `ready` در این کتابخانه فقط برای کنترلر مورد اعتماد است؛ خود کتابخانه صحت امضا یا عبور گزارش کیفیت را اثبات نمی‌کند. اتصال کنترلر اعتبارسنجی و امضا شرط استفادهٔ عملیاتی از آن است.

## شواهد موجود

Build و typecheck همهٔ workspaceها موفق بوده است. ۱۲۱ آزمون محلی موفق‌اند؛ آزمون‌های وابسته به محیط در اجرای محلی ویندوز skip می‌شوند. هر ۹ آزمون بستهٔ release، شامل ۶ آزمون یکپارچه، روی PostgreSQL واقعی VM موفق بوده‌اند؛ این اجرا هنگام ورود PBF نیز تکرار شد.

آزمون Python شامل پنج حالت اصلی موفق است. فایل ساختگی توسعه‌یافته با ۱۵۲ node، ۳۹ way و ۵ relation روی importer واقعی وارد شد؛ digest همهٔ primitives پس از بازیابی دقیقاً با ورودی برابر بود. این آزمون شامل دادهٔ بدون tag، نام فارسی، نویسهٔ غیر BMP، ترتیب کلیدها، اعضای تکراری و مرتب relation، metadata و ساختار خالی است. کاشی fixture نیز محتوای قابل تولید داشت.

مبنای سورس: آرشیو اصلی با SHA-256 برابر `2b9fa26009824c6a8e85d8475f67f9fbbb9d2cc25a51ebb8a1a086bff68cfc8d`؛ هر ۱۷۶ ورودی فهرست checksum بسته تأیید شد. نسخهٔ اصلی روی Desktop تغییر نکرده است.

## ممیزی ورودی ایران

فایل `iran-261025.osm.pbf`، اندازهٔ ۲۲۹٬۹۲۱٬۸۵۹ بایت و SHA-256:

```text
a3c61d35b010d4a474c1eabdef9500339472743423d7bb895b16241c08eb4065
```

| داده | تعداد |
|---|---:|
| node | 27,005,066 |
| way | 3,396,793 |
| relation | 99,073 |
| node بدون tag | 26,156,804 |
| way بدون tag | 206,877 |
| relation بدون tag | 17 |
| ارجاع way به node | 31,825,062 |
| ارجاع way به node مفقود | 0 |

ترتیب و یکتایی primitives تأیید شد. نسخه و timestamp همهٔ ۳۰٬۵۰۰٬۹۳۲ شیء موجود است؛ changeset، uid و user در این منبع غایب‌اند و ساخته نمی‌شوند. timestamp snapshot در header برابر `2026-10-25T21:21:21Z` است. گسترهٔ nodeها از مرز سیاسی ایران وسیع‌تر است؛ وجود اعضای تکمیلی و روابط منطقه‌ای باید در سیاست پذیرش extract لحاظ شود.

در relationها ۳۹٬۴۵۳ ارجاع way، تعداد ۸۹۹ ارجاع relation و ۲۸۳ ارجاع node مفقود است. وضعیت ورودی `review_required` است. این اعداد تعداد ارجاع‌اند، نه تعداد عوارض مستقل آسیب‌دیده؛ پیش از تصویب سیاست استثنا باید پراکندگی و اثر آن بر هندسه/قابلیت‌ها بررسی شود. واردسازی آزمایشی برای این بررسی مجاز است؛ این گزارش مجوز انتشار خودکار نیست.

منبع Geofabrik توسط کاربر اعلام شده است. hash یکسان بودن کپی‌ها را اثبات می‌کند؛ امضای ناشر یا checksum رسمی منبع مستقل تأیید نشده است. صحت میدانی عوارض نیز از ممیزی فایل نتیجه نمی‌شود.

## نتیجهٔ اجرای واقعی

واردسازی آزمایشی ایران ۹۸۹ ثانیه طول کشید و شمارش تمام primitives و ارجاع‌ها برابر ورودی بود. سپس همهٔ رکوردهای `osm_raw` از snapshot خواندنی بازیابی شدند؛ digest هر سه گروه دقیقاً برابر ورودی بود. بنابراین حفظ داده برای همین فایل، شامل metadata موجود، tags و ترتیب ارجاع‌ها، به‌صورت کامل بررسی شد. اعتبار واقعی جغرافیا یا پشتیبانی نمایشی همهٔ tagها از این نتیجه استنتاج نمی‌شود.

این زمان import مربوط به نخستین اجرا روی PostgreSQL 17.5/PostGIS 3.5.2 است. تعریف نهایی آرشیو index تکراری ندارد و بازنویسی مکانی جدول خام را انجام نمی‌دهد؛ تعریف نهایی با fixture واقعی مجدداً آزموده شد. زمان import فایل ایران با این تنظیم نهایی دوباره اندازه‌گیری نشده است.

مقایسهٔ نخست کاشی‌ها اختلافی در ساده‌سازی یک چندضلعی آشکار کرد. GEOS تصویر اولیه نسخهٔ 3.9.0 بود و این رفتار با [اشکال مستند ناپایداری ساده‌سازی Multi geometry](https://github.com/libgeos/geos/pull/718) سازگار بود. یک backup منطقی ساخته شد و داده در volume تازه روی PostgreSQL 17.11/PostGIS 3.6.4/GEOS 3.14.1 بازیابی شد؛ volume قبلی محفوظ ماند. با توجه به [تغییر سیستم‌عامل تصویر رسمی PostGIS](https://github.com/postgis/docker-postgis)، انتقال با dump/restore انجام شد. پس از بازیابی، تطابق معنایی تمام primitives دوباره تأیید شد و هر ۷۲ مقایسهٔ MVT در سه دور، بین Martin، pg_tileserv و تابع مستقیم دیتابیس موفق شد. تعریف تابع اکنون GEOS قدیمی‌تر از profile بررسی‌شده را رد می‌کند.

حجم دیتابیس پس از حذف indexهای تکراری ۵٬۴۶۲٬۸۰۸٬۲۴۳ بایت است؛ این اصلاح ۶۸۵٬۱۳۷٬۹۲۰ بایت آزاد کرد و دادهٔ ردیف‌ها را تغییر نداد. این اندازه شامل آرشیو خام و catalog نمایشی است؛ backup، volume قبلی، imageها، فضای موقت build و موتورهای جست‌وجو/مسیریابی را شامل نمی‌شود.

تمام هندسه‌های **موجود** در هشت جدول نمایشی معتبر و غیرخالی بودند:

| لایه | ردیف |
|---|---:|
| water | 14,056 |
| landcover | 183,887 |
| waterways | 98,031 |
| boundaries | 30,984 |
| transport | 2,150,894 |
| buildings | 633,856 |
| places | 62,238 |
| pois | 329,509 |

این اعداد تعداد ردیف‌اند؛ یک primitive ممکن است در چند لایه/ردیف ظاهر شود. catalog موجود ۵۴۸٬۷۵۵ node، تعداد ۱۲۷٬۰۱۱ way و ۱۰٬۱۰۷ relation را در `uncatalogued` نگه می‌دارد. پشتیبانی معنایی/نمایشی آن‌ها باید در N-03 تعیین شود؛ آرشیو خام هیچ‌یک را حذف نکرده است. نبود هندسهٔ نامعتبر در خروجی، اثبات تبدیل موفق تمام ورودی‌ها نیست.

ارجاع‌های way مفقود در relationها شامل ۴۹ رابطهٔ route، تعداد ۱۵۸ boundary و ۹ multipolygon است؛ بقیه در گزارش تفصیلی آمده‌اند. شمارش گروه‌های member مختلف می‌تواند به یک relation مشترک مربوط باشد. پیش از انتشار باید اثر جغرافیایی و سیاست پذیرش آن‌ها تعیین شود.

سنجش اولیه با ۴۸ درخواست گرم‌سازی، سپس ۹۶ درخواست برای هر موتور، چهار دور و هم‌زمانی ۴ انجام شد. کلاینت یک CPU داشت، هر درخواست اتصال HTTP تازه ساخت و داخل شبکهٔ Docker اجرا شد. cache برنامهٔ HTTP غیرفعال و bufferهای PostgreSQL مشترک و گرم بودند؛ بودجهٔ دیتابیس ۲٫۵ CPU/۵ GiB و هر tile server یک CPU/۵۱۲ MiB بود.

| موتور | خطا | میانه ms | صدک ۹۵ ms | بیشینه ms |
|---|---:|---:|---:|---:|
| Martin 1.16.1 | 0 | 36.774 | 440.724 | 630.693 |
| pg_tileserv با digest ثابت | 0 | 31.709 | 481.885 | 633.441 |

این نمونه برندهٔ قطعی کارایی یا ظرفیت عملیاتی تعیین نمی‌کند. Martin با نسخهٔ مشخص، منابع صریح و عبور از کنترل صحت، مبنای ادامهٔ پیاده‌سازی است. ارزیابی بار واقعی، cache/gateway، مرورگر و هم‌زمانی build/سرویس‌دهی باقی است.

هر ۹ آزمون release روی PostgreSQL جدید نیز موفق شد. CI شاخهٔ بازبینی build، typecheck، آزمون‌های workspace، کنترلر release روی PostgreSQL واقعی و آزمون parser را اجرا می‌کند. شواهد ماشین‌خوان در [evidence](evidence/2026-10-27/) ثبت شده‌اند.

## بخش‌های باقی‌مانده

مسیر تحویل خودکار، quarantine بادوام، صف دارای بازیابی/مهار worker قدیمی، کنترلر build همهٔ موتورها، پذیرش موارد غیرعادی، مدیریت کلید و امضا، gateway نسخه‌دار، اتصال نشست به وب، GC واقعی، backup/restore و آزمون بار/خرابی/انتشار بدون قطعی هنوز تکمیل نشده‌اند. مسیرهای فعال نمونهٔ قبلی همچنان Tegola را مصرف می‌کنند. جایگزینی عملیاتی فقط پس از تکمیل این قراردادها و آزمون سرتاسری انجام خواهد شد.

اطلاعات SSH، کلید دسترسی، credential، خود PBF و state خصوصی VM وارد Git نشده‌اند. سرویس‌های کاشی آزمایش تنها در شبکهٔ داخلی Docker در دسترس‌اند؛ gateway/مرورگر عمومی جدید در این مرحله راه‌اندازی نشده است.
