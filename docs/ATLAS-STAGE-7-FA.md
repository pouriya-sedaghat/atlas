# مرحلهٔ هفتم Atlas: تشخیص بدون بار سنگین و شاهد بیرون از VM

تاریخ: ۲۰۲۶-۱۰-۲۹؛ timestampهای شواهد UTC هستند. طبق پاسخ کاربر، VM روی **میزبان Windows/VMware دیگری** اجرا می‌شود. دسترسی آن میزبان هنوز داده نشده است. بنابراین دادهٔ این ویندوز، مشخصات میزبان واقعی VM محسوب نشده است.

## یافته‌های قابل اتکا

لاگ kernel در بازهٔ ۰۵:۵۲ تا ۰۵:۵۸ UTC، خطای disk reset یا OOM ثبت‌شده نشان نداد؛ یک AppArmor denial مربوط به برنامهٔ `who` وجود دارد. لاگ open-vm-tools در همان بازه ورودی ندارد. نبود پیام در این دو لاگ، وقفهٔ مجازی‌ساز یا اختلال storage میزبان را رد نمی‌کند.

sysstat تاریخی، فقط نمونه‌های حدود ده‌دقیقه‌ای داشت. در نمونهٔ منتهی به ۰۶:۰۰:۰۲ UTC، میانگین await در sda برابر **۴۰٫۶۰ ms** و در dm-0 برابر **۷۲۴٫۶۹ ms** بود؛ در نمونهٔ قبل، این دو عدد ۶٫۲۷ و ۱۴٫۷۵ ms بودند. این دو لایه جمع نمی‌شوند. اختلاف می‌تواند شامل صف و throttle لایه‌ای باشد و اثبات سرعت دیسک فیزیکی نیست. میانگین ده‌دقیقه‌ای محل و علت وقفهٔ ۱۶٫۹۹۷ ثانیه‌ای قبلی را مشخص نمی‌کند.

در همان نمونهٔ تاریخی، swap-in/out مهمان صفر و حافظهٔ available حدود ۱۰٬۰۳۹٬۰۷۲ KiB بود. این اعداد مربوط به مهمان و میانگین/نمونهٔ همان ابزارند؛ کمبود حافظهٔ **میزبان** از آن‌ها قابل ردکردن نیست. ROTA=1 و مدل VMware Virtual S داخل مهمان نیز نوع HDD/SSD فیزیکی را ثابت نمی‌کند. سرویس open-vm-tools فعال است؛ مشکل به «نصب‌نبودن Tools» نسبت داده نشد. سرویس مشخصِ بلااستفاده‌ای با رابطهٔ اثبات‌شده به خطا پیدا نشد و توقف حدسی سرویس‌ها انجام نشد.

## شاهد مستقل

یک collector سبک و فقط‌خواندنی در مهمان و شاهد HTTP روی کامپیوتر خارج از VM ساخته شد. ساعت این شاهد از event loop مهمان مستقل است. تونل موقت SSH، فقط روی loopback باز و پس از پایان بسته می‌شود؛ نام کاربر/کلید/پیکربندی خصوصی وارد artifact عمومی نمی‌شود. endpoint واقعی Martin و هویت ابزار مهمان با hash کنترل شد و کاشی‌ها با hash ثبت‌شدهٔ قبلی مقایسه شدند. برنامه، ساخت و انتشار را فعال نمی‌کند.

سه اجرای کم‌بار ثبت شدند:

| اجرا | مدت درخواستی مهمان | نمونهٔ مهمان | درخواست HTTP | خطا |
|---|---:|---:|---:|---:|
| نخست | ۱۲۰ ثانیه | ۱۲۰ | ۱۰۳ | ۰ |
| پس از حفظ دقیق timestampهای بزرگ JSON | ۶۰ ثانیه | ۶۰ | ۴۸ | ۰ |
| نسخهٔ نهایی با حفاظت گزارش و کنترل تغییر سورس | ۳۰ ثانیه | ۳۰ | ۲۳ | ۰ |

گزارش نخست بیشینهٔ HTTP برابر ۸۰۰٫۸۱۸ ms، بیشینهٔ فاصلهٔ نمونه‌های مهمان حدود ۱۲۳۹ ms و بیشینهٔ فاصلهٔ دریافت آن‌ها حدود ۱۴۵۴ ms داشت؛ بیشینهٔ event-loop delay شاهد بیرونی حدود ۵۷ ms بود. این اجرای کم‌بار وقفهٔ قبلی را بازتولید نکرد. تعداد متفاوت probeها به زمان پاسخ، فاصلهٔ درخواست‌ها و پایان نمونه‌برداری مربوط است؛ تعداد نمونهٔ زمان‌بندی‌شدهٔ بیشتر ساخته نشده است. رکورد نهایی مهمان، تعداد نمونه‌ها و هویت کانتینرها کنترل شدند.

موفقیت این اجراها **رفع مشکل I/O یا پذیرش بدون‌اختلال زیر بار نیست**. مسیر اندازه‌گیری، تونل و SSH را نیز شامل می‌شود و HTTP عمومی gateway نیست. سقف HTTP پنج ثانیه و معیارهای قبلی پذیرش ایران افزایش نیافتند. معیار پیوستگی ۲٫۵ ثانیه در این ابزار، معیار کیفیت جمع‌آوری تله‌متری است، نه SLA تازهٔ نقشه. شکست خواندن metric به‌صورت null و خطای صریح صادر می‌شود؛ قطعی collector با صفر خطا پوشانده نمی‌شود. گزارش‌های کاملِ خام با gzip بدون تغییر محتوا نگهداری شده‌اند.

## ابزار میزبان آماده است؛ نتیجهٔ میزبان هنوز موجود نیست

`collect-windows-host.ps1` تنظیمات منتخب و فاقد بخش رمزنگاری VMX، metadata دیسک/snapshot، شاخص‌های RAM/paging/I/O میزبان، مصرف فرایند VMware و بخش‌های مرتبط لاگ را جمع می‌کند. هیچ VMDK/VMEM کپی یا خوانده نمی‌شود، تنظیمات VM و سرویس‌ها تغییر نمی‌کنند و مسیر خروجی باید تازه و بیرون از VM باشد. Counterهای ناموجود یا با Status نامعتبر، شاهد سلامت نیستند.

اسکریپت روی همین ویندوز، با VMX و لاگ **ساختگی** آزموده شد: مقادیر سخت‌افزاری مجاز باقی ماندند، marker کلید خصوصی ساختگی و marker رمز وارد خروجی نشدند، خطاهای دسترسی صریح ماندند و فایل VMX تغییر نکرد. این آزمون، دادهٔ میزبان واقعی نیست. آزمون اولیه یک ناسازگاری تبدیل generic list در PowerShell را آشکار کرد؛ پس از اصلاح، اجرای کامل و checksumها موفق شدند. دو آزمون Node از گزارش موجود و مسیر remote نامعتبر حفاظت می‌کنند؛ دو آزمون Python نیز missing/oversized metric را با خطای صریح می‌خواهند.

راهنمای اجرای دقیق و فرمان آماده در [راهنمای جمع‌آوری](../tools/diagnostics/README-FA.md) است. تنها اقدام لازم از سمت میزبان، اجرای collector روی **همان میزبان Windows واقعی VM** و ارائهٔ پوشهٔ خروجی در این گفتگو است. دسترسی فعلی ما به SSH مهمان، امکان اندازه‌گیری مستقیم دیسک فیزیکی، paging یا رویدادهای VMware در میزبان دیگر را نمی‌دهد.

## وضعیت و ادامه

مقایسهٔ قبل/بعد، jobها، سیاست paused و هویت کانتینرها را کنترل می‌کند. هیچ ساخت سنگین، import ایران، retry candidate، تغییر quota، تغییر VMware، حذف دیتابیس یا انتشار انجام نشده است. پیش‌نویس‌های مراحل قبل ادغام نشده‌اند. شرط پذیرش ایران و وظیفهٔ N-12 همچنان بازند.

پس از دریافت دادهٔ میزبان، ابتدا کمبود حافظه/paging، صف و تأخیر storage، رشد یا snapshot دیسک و پیام‌های توقف/ازسرگیری مجازی‌ساز با زمان خطا تطبیق داده می‌شوند. انتخاب راه‌حل، نتیجهٔ آن بررسی خواهد بود؛ خاموش‌کردن حدسی ویژگی‌های VMware یا بالا بردن timeout جای آن را نمی‌گیرد. تا آن زمان، سازنده paused می‌ماند.
