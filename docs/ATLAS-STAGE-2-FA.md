# وضعیت مرحلهٔ دوم Atlas: ورود بادوام و پذیرش منبع

تاریخ: ۲۰۲۶-۱۰-۲۷. مسیر تحویل خصوصی، صف بازیابی‌پذیر، اعتبارسنجی جداشده و امضای پذیرش منبع در VM پیاده و آزموده شده‌اند. این مرحله هنوز سازنده یا منتشرکنندهٔ نسخهٔ نقشه نیست. مسیر فعال نمونهٔ قبلی همچنان Tegola را مصرف می‌کند؛ اتصال Martin، همهٔ موتورهای وابسته، gateway و کلاینت باقی است.

## رفتار پیاده‌شده

اپراتور با دستور `submit` فایل کامل‌شده را تحویل می‌دهد. ابزار کپی خصوصی، SHA-256، manifest و marker نهایی `READY` را می‌سازد؛ فایل نیمه‌کپی‌شده پردازش نمی‌شود. worker از هر تحویل snapshot خصوصی می‌گیرد و فقط پس از اثبات اندازه و hash، نسخهٔ اصلی تغییرناپذیر را در مخزن مبتنی بر hash ثبت می‌کند. نسخهٔ موقت تحویل بعد از checkpoint بادوام حذف می‌شود؛ فایل اصلی اپراتور دست‌نخورده می‌ماند.

صف در PostgreSQL با lease، heartbeat، token مخصوص هر تلاش و تراکنش‌های کوتاه کار می‌کند. فقط یک کار سنگین در هر instance اجرا می‌شود. worker قدیمی پس از انقضای lease نمی‌تواند نتیجه ثبت کند. retry زیرساخت محدود است؛ کمبود ظرفیت به انتظار منجر می‌شود و سهم خطای ورودی را مصرف نمی‌کند. تحویل یکسان با همان specification و provenance گزارش قبلی را دوباره استفاده می‌کند.

بررسی PBF در کانتینر بدون شبکه، بدون credential/کلید، بدون دسترسی Docker، با filesystem فقط‌خواندنی، کاربر غیر root، حذف capabilityها و سقف CPU/RAM/pid/زمان انجام می‌شود. parser فقط PBF را می‌بیند. تفسیر نام فایل یا محتوای آن به‌عنوان دستور مجاز نیست. مسیرهای داخلی با descriptor و `O_NOFOLLOW` باز می‌شوند؛ symlink، hardlink، FIFO و تغییر حین تحویل رد می‌شوند.

ورودی عادی خودکار به signer می‌رسد. موارد غیرعادی به `review_required` می‌روند. تأیید انسانی دقیقاً به hash گزارش و تصمیم، هویت ثبت‌کننده و دلیل متصل است؛ شکست قطعی ساختاری قابل تأیید نیست. signer سیاست، baseline، گزارش و بایت‌های منبع را دوباره کنترل می‌کند، رسید را امضا و امضایش را بررسی می‌کند و سپس پذیرش را ثبت می‌کند. امضای آزمایشگاهی ما، امضای ناشر Geofabrik محسوب نمی‌شود.

رسید شامل hash منبع، گزارش، تصمیم، policy، image اعتبارسنج و نسخهٔ مستقل collector و signer است. گزارش collector قدیمی فقط با اعتماد صریح به همان build و تطابق policy/image قابل استفاده است. ارتقای signer باعث نسبت دادن گزارش قدیمی به کد جدید نمی‌شود.

## نتیجهٔ واقعی فایل ایران

فایل ۲۲۹٬۹۲۱٬۸۵۹ بایتی با SHA-256 زیر در مسیر جدید دوباره به‌طور کامل ممیزی شد:

```text
a3c61d35b010d4a474c1eabdef9500339472743423d7bb895b16241c08eb4065
```

parser محدودشده ۸۶۸٫۳۴ ثانیه کار کرد؛ کل تلاش شامل snapshot، hashها و ثبت نتیجه حدود ۹۰۶٫۷ ثانیه بود. این اندازه‌گیری مربوط به همین VM، فایل و شرایط cache است و مبنای ظرفیت عملیاتی نیست. سقف parser برابر ۳ GiB RAM بدون swap و ۱٫۵ CPU بود؛ VM چهار CPU و ۱۲ GiB RAM دارد.

شمارش ۲۷٬۰۰۵٬۰۶۶ node، تعداد ۳٬۳۹۶٬۷۹۳ way و ۹۹٬۰۷۳ relation، همهٔ digestهای معنایی و شمار ارجاع‌های مفقود دقیقاً با ممیزی مستقل مرحلهٔ اول برابر بودند. ارجاع way به node مفقود صفر است. ارجاع‌های relation مفقود شامل ۳۹٬۴۵۳ way، تعداد ۸۹۹ relation و ۲۸۳ node است. اثر جغرافیایی و پوشش این موارد هنوز باید تعیین شود؛ در بررسی مرحلهٔ اول گروه‌های دارای way مفقود شامل ۴۹ route، تعداد ۱۵۸ boundary و ۹ multipolygon بودند.

نتیجهٔ ثبت‌شده:

| فیلد | مقدار |
|---|---|
| validation | `df5ed7ffabe9108dcf8288770104dabd` |
| state | `review_required` |
| دلایل | `incomplete_relation_members` و `initial_baseline_required` |
| report SHA-256 | `9ff866f094123cdf807782d56e215fb5ea856a3da6dd3df79827eab623b68bc7` |
| decision SHA-256 | `002de966ddff3d4c2c52f15e870bdef21a0554fa9d09fe5bf8c00d7a9c53a0fa` |
| امضا / پذیرش / baseline | انجام نشده |

منبع توسط کاربر Geofabrik اعلام شده است. checksum یا امضای مستقل ناشر تأیید نشده؛ policy صرفاً namespace اعلام‌شده را کنترل می‌کند. فایل اصلی روی ویندوز و نسخهٔ دستی VM حذف نشده‌اند. ورودی کانُنیکال خصوصی یک نسخهٔ بایتی از این PBF نگه می‌دارد.

در حین ممیزی ایران، ۱۲۰ درخواست به کاشی‌های Martin موجود در شبکهٔ داخلی بدون خطا پاسخ گرفتند. این شاهد فقط سرویس‌دهی هم‌زمان با **اعتبارسنجی** است؛ آزمون انتشار کامل، مرورگر، import هم‌زمان یا تضمین نبود قطعی نیست.

## آزمون‌ها و استقرار آزمایشی

- Build و typecheck تمام workspaceها موفق بود؛ ۱۲۶ آزمون محلی موفق و ۱۵ آزمون وابسته به محیط در ویندوز skip شدند.
- هر ۱۱ آزمون بستهٔ intake، شامل ۶ آزمون تراکنشی، روی PostgreSQL واقعی موفق شدند. پنج آزمون حملات filesystem نیز روی Linux موفق شدند.
- یازده سناریوی سرتاسری با Docker، PostgreSQL و Cosign واقعی روی دیتابیس موقت و PBFهای ساختگی موفق شدند: پذیرش عادی، dedup، رد way ناقص، رد PBF خراب، توقف anomaly، symlink، دست‌کاری امضاشده، محدودیت نقش worker، اعتماد صریح به collector قبلی، ثبت ورودی در حین lease فعال و پاک‌سازی container منقضی با حفاظت کار معتبر/نامرتبط.
- worker، signer و reconcile timer با systemd user و linger فعال‌اند؛ کد اجراشده در پوشهٔ دارای build hash نصب شد. پس از SIGKILL به worker بیکار، systemd آن را با PID جدید بازیابی کرد. این آزمون reboot VM یا بازیابی کل میزبان نیست.
- برای سه کانتینر موجود آزمایشگاه restart policy فعال شد؛ زمان شروع آن‌ها تغییر نکرد و برای این کار restart نشدند.

در ساخت نخست image آزمایشی، dependency بومی expat غایب بود و سپس permission فایل parser اشکال داشت. هر دو به خطای زیرساخت و توقف پذیرش منجر شدند؛ هیچ منبعی از این مسیر پذیرفته نشد. image نهایی dependency ثابت دارد و entrypoint غیر root را هنگام build اجرا می‌کند. سابقهٔ شکست و گزارش تشخیصی خصوصی حفظ شده است.

شواهد ماشین‌خوان، رسید امضاشدهٔ **fixture**، bundle و کلید عمومی آزمایش در [evidence](evidence/2026-10-27-intake/README.md) آمده‌اند. رسید ساختگی مجوز انتشار ایران نیست. CI علاوه بر آزمون‌های PostgreSQL، image واقعی parser را می‌سازد و fixture را در sandbox اجرا می‌کند.

| parser image محلی | `sha256:e422aad6876ad15083c0c8118f0a3f3814f98cf5bfa56e39828907acee9fde90` |

شناسهٔ image فوق شناسهٔ محلی همان artifact اجراشده است؛ build مجدد روی میزبان دیگر الزاماً image ID یکسان تولید نمی‌کند. مبنای build، imageها و wheel دارای digest ثابت‌اند. Cosign نسخهٔ 3.1.4 با SHA-256 باینری ثابت اجرا شد؛ الگوی blob signing در [مستند Sigstore](https://docs.sigstore.dev/cosign/signing/signing_with_blobs/) آمده است.

## محدودیت و ادامهٔ لازم

کلید امضای فعلی، کلید **آزمایشگاهی محلی** است. کلید رمزگذاری شده، password، DSN و PBF وارد Git نشده‌اند. parser از آن‌ها جداست؛ اما coordinator دارای Docker و signer روی حساب مالک مشترک هستند. نقش‌های SQL و processهای جدا، مرز امنیتی در برابر تسخیر میزبان نیستند. KMS/هویت مستقل signer، احراز هویت واقعی reviewer، rotation/revocation و backup/restore کامل هنوز لازم‌اند.

GC واقعی منبع/رسید، ظرفیت‌سنجی طولانی‌مدت و مهاجرت خودکار صف بین buildها تکمیل نشده‌اند. پوشهٔ incoming سقف محافظ ۱۰٬۰۰۰ شناسه دارد و metadata مصرف‌شده فعلاً برای ممیزی باقی می‌ماند. قبل از استفادهٔ مداوم، archival امن آن باید پیاده شود. آدرس خصوصی دیتابیس پس از بازسازی شبکهٔ Docker باید کنترل شود؛ آزمون بازیابی کامل میزبان هنوز انجام نشده است.

پیش از انتشار، باید پوشش featureها و اثر relationهای ناقص روشن شود، build نسخه‌دار تمام backendهای لازم ساخته و تأیید شود، gateway/نشست/کلید cache به کلاینت متصل شوند و rollback و GC واقعی زیر بار و خرابی آزموده شوند. پذیرش احتمالی همین منبع نیز به‌تنهایی اجازهٔ انتشار نیست. مراحل بعدی مطابق نیاز می‌توانند موتورهای دیگر را اصلاح کنند.

روش اجرا، قرارداد تحویل و review و محدودیت‌های ارتقا در [راهنمای intake](../infra/atlas/intake/README.md) ثبت شده است. وظایف قبلی در [backlog](seyra-backlog-fa.md) حفظ شده‌اند.
