# نسخهٔ کامل و اصلاح‌شدهٔ سورس دمو — ۲۶ اکتبر ۲۰۲۶

این آرشیو تمام سورس نسخهٔ استخراج‌شدهٔ دمو را یکجا دارد: برنامه‌های API، وب و عملیات، بسته‌های قرارداد و دارایی نقشه، Dockerfileها، تعریف سرویس‌ها، pipeline ورود داده، Swagger/OpenAPI، آزمون‌ها و راهنمای اجرا. اصلاح خطای `spawnSync git ENOENT` در مسیر آماده‌سازی یکپارچه است و برای نصب تازه نیازی به ZIP اصلاحی جداگانه نیست.

مبنای سورس همان نسخه‌ای است که روی VM شما اجرا و در لاگ ارسالی تأیید شده است:

- مخزن: `pouriya-sedaghat/seyra`
- شاخه: `feat/map-services-v1`
- commit: `80935b42a9b5616c21df7483412c5fb2ccbc6df8`
- سرویس‌ها: Tegola/PostGIS، Valhalla، Photon، Overpass، API و رابط نقشه/Swagger
- اجرای دمو: HTTP، پورت پیش‌فرض 8080، بدون CA/PKI برنامه

سورس جدیدتری از GitHub وارد این نسخه نشده و هیچ تغییری در GitHub ثبت نشده است. `SOURCE.json` و `EXTRACTION.patch` منشأ و تغییرات محلی را ثبت می‌کنند. `SHA256SUMS` تمام فایل‌های همین ZIP را پوشش می‌دهد.

## نتیجهٔ اجرای VM

لاگ ارسالی شما، موفقیت مرحلهٔ نهایی آماده‌سازی و تأیید هر ۱۰ image، ورود دادهٔ `iran-261017.osm.pbf`، فعال‌سازی release ‌`ds-20261017-2fe22e532682` و آزمون HTTP نقشه و Swagger را نشان می‌دهد. جزئیات در `VM_VALIDATION.md` و `validation/owner-vm-evidence.json` است. بررسی بصری مرورگر، آزمون از یک دستگاه جداگانهٔ LAN و سنجش ظرفیت/کیفیت کل داده هنوز به این گزارش اضافه نشده‌اند.

## نصب تازه

پس از استخراج ZIP در یک پوشهٔ تازه و آماده بودن Docker، Compose، Buildx و ابزارهای میزبان:

```bash
sha256sum -c SHA256SUMS
sudo bash scripts/prepare.sh
sudo bash demo.sh --pbf /absolute/path/to/region.osm.pbf
```

راهنمای کامل در `README-FA.md` است. برای تنظیمات شبکهٔ تأییدشدهٔ شما:

```bash
sudo bash demo.sh --pbf /home/owner/data/iran-261017.osm.pbf \
  --bind 172.16.20.46 --cidrs 172.16.20.0/24 --port 8080
```

## استفاده روی VM فعلی

این آرشیو سورس است؛ برای آرشیو، بررسی کد یا نصب تازه استفاده می‌شود. برای دریافت این نسخه نیازی به توقف VM فعلی یا import مجدد ندارید. آن را در پوشه‌ای جدا از نصب در حال اجرای خود استخراج کنید تا lock تولیدشده و `.demo-state` فعلی حفظ شوند.

imageهای Docker، `node_modules`، دادهٔ واقعی OSM، دیتابیس/indexهای ساخته‌شده، secretها و state اجرایی در ZIP سورس قرار ندارند. شناسه‌های image در lock اولیه عمداً null هستند؛ آماده‌سازی برای هر میزبان، شناسه‌های واقعی imageهای همان میزبان را ثبت می‌کند. شناسه‌های مشاهده‌شده روی VM شما صرفاً در گزارش شواهد نگهداری می‌شوند و جایگزین lock یک نصب تازه نیستند.
